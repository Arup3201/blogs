This blog provides an example implementation of instrumenting API code with Prometheus to get metrics data in Go language.

Library: github.com/prometheus/client_golang

First, the metric need to be created,

```go
var (
	http_requests_count = prometheus.NewCounterVec(
		prometheus.CounterOpts{
			Name: "http_requests_total",
			Help: "Total count of HTTP requests",
		},
		[]string{"method", "endpoint", "status_code"},
	)
	http_request_duration = prometheus.NewHistogramVec(
		prometheus.HistogramOpts{
			Name: "http_request_duration_seconds",
			Help: "Latency of HTTP requests in seconds",
		},
		[]string{"method", "endpoint", "status_code"},
	)
)
```

A _counter_ is a cumulative metric that represents a single monotonically increasing counter which can only increase or reset to zero. Example of counter values are total count of HTTP requests, errors or tasks completed etc.

A _histogram_ records observations (such as request duration in seconds or response size) by counting them in configurable buckets. It also provides a sum of observed values.

Example of how _histogram_ works - buckets are defined e.g. lower or equal 0.3, le 0.5, le 0.7, le 1 and le 1.2. All the buckets that have higher boundaries than the current value will be incremented. If the value is 0.25 then the values will be -

| Bucket | Count |
| ------ | ----- |
| le 0.3 | 1     |
| le 0.5 | 1     |
| le 0.7 | 1     |
| le 1   | 1     |
| le 1.2 | 1     |

For next value 0.8,

| Bucket | Count |
| ------ | ----- |
| le 0.3 | 1     |
| le 0.5 | 1     |
| le 0.7 | 1     |
| le 1   | 2     |
| le 1.2 | 2     |

Notice that all the values after le 1 is incremented by 1. Because it is a cumulative metric.

Going back to the code in Go, you might notice `CounterVec` and `HistogramVec` with _Vec_. It stands for vector. Vectors means one data point will contain multiple information. For example, HTTP method, endpoint and status code.

Next, we need to register the metric to Prometheus registry

```go
func init() {
	prometheus.MustRegister(http_requests_count)
	prometheus.MustRegister(http_request_duration)
}
```

After registering the metric, a middleware can monitor the HTTP requests

```go
func PrometheusMiddleware(next http.Handler) http.Handler {
	return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
		startTime := time.Now()
		ww := &responseWriter{w, http.StatusOK}

		next.ServeHTTP(ww, r)

		statusCode := strconv.Itoa(ww.statusCode)

		http_requests_count.WithLabelValues(r.Method, r.URL.Path, statusCode).Inc()
		http_request_duration.WithLabelValues(r.Method, r.URL.Path, statusCode).Observe(time.Since(startTime).Seconds())
	})
}
```

Here `responseWriter` is an implementation of the `http.ResponseWriter` interface.

There is also a need for exporter which is another handler to translate metric into Prometheus format.

```go
func MetricHandler() http.Handler {
	return promhttp.Handler()
}
```

Finally, the handler will be attached to the `/metrics` endpoint so that Prometheus can scrap the target. The middleware will be attached to the server handler so that it can monitor all the HTTP requests.

I also have to include the target in the Prometheus configuration file,

```yml
global:
  scrape_interval: 15s
  evaluation_interval: 15s

rule_files:
  # - "first_rules.yml"
  # - "second_rules.yml"

scrape_configs:
  - job_name: "prometheus"
    static_configs:
      - targets: ["localhost:9090"]
  - job_name: "task_server"
    static_configs:
      - targets: ["localhost:8080"]
```

At last, run Prometheus by loading this configuration,

```sh
./prometheus --config-file=prometheus.yml
```

I can monitor the API at `localhost:9090` and query the metrics using PromQL.
