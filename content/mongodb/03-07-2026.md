Before reading about the embedding and references, some concepts should be understood first.

MongoDB has the following types of relationships -

1. One-one: One movie is launched by one studio.
2. One-many: One movie can have multiple casts.
3. Many-many: Multiple movies can be shown in multiple theaters.

Each document is an entity and the field-value pairs are the attribute of that entity.

There are two ways to represent relationships - embedding and reference. Depending on the type of relationship and specific situation, the representation can vary.

It will be easy to understand the two methods with a movie example.

A movie can belong to multiple genres. So, genres can be part of the movie document. It is embedding.

Whereas a movie can be shown in multiple theaters. And a theater entity can have multiple attributes. In that case, movie can store reference IDs of the theaters in an array and theater can store reference IDs of the movies in an array. This is referencing.

Embedding is useful when two entities are required at the same time. If there are thousands of movies and only 40 genres, and when movies are shown, the genres they are part of should be shown while genres should also show all the movies they are part of. Embedding the genres in a movie as an array will save the complexity of querying the genres or movies separately.

But, if the theater data is shown separately from movie. It is not required to query the movie while querying the theater - referencing the movies inside theater document as array of reference IDs reduces the document size.
