# Distributed Database Architecture

MongoDB follows a distributed system architecture like other non-relational databases. Distributed architecture means that the data is stored in multiple machines or nodes. The nodes may be in different geographic locations.

Because the data is shared across multiple machines, if one machine fails the system can still function due to the redundancy. A distributed architecture provides consistent service and reliability even in case of system failure.

Distributed data can also be closer to where it is generated or accessed. It reduced the latency and enhances the user experience.

# Document Model

MongoDB uses document model to store data. Document model uses JSON format to represent data. JSON is a lightweight data format that is readable by human and easily parsable by machines.

Here is an example document in JSON,

```json
{
  "_id": 1,
  "name": {
    "first": "Ada",
    "last": "Lovelace"
  },
  "title": "The First Programmer",
  "interests": ["mathematics", "programming"]
}
```

You can easily more fields,

```json
{
  "_id": 1,
  "name": {
    "first": "Ada",
    "last": "Lovelace"
  },
  "title": "The First Programmer",
  "interests": ["mathematics", "programming"],
  "address": "100 St John Street London",
  "parents": ["Lord Byron", "Lady Byron"]
}
```

Multiple documents make up a collection. The above example is taken from users collection.

Document model is unique because it can handle polymorphic data and supports flexible schemas.

Polymorphic means the data can take multiple types within the same structure. To allow for polymorphic documents, MongoDB also allows for flexible schemas. Flexible schema allows each data to have unique structure permitting various data types and fields within the same collection. It is especially useful when dealing with unstructured or semi-structured data that does not fit neatly in a table.

# Flexible Schema

Imagine a social media app that stores different posts of users. Each post will have common fields like user_id, timestamp and likes. It will also have varying field. It supports different formats of post.

- Text: content
- Image: image_url, caption
- Video: video_url, title, duration

MongoDB allows for each document in a collection to have different structure, making it easy to store different types of content without needing multiple collections or complex data models. This means as the application evolves, new type of posts can be easily added into the schema.
